# 社内サーバー利用状況ダッシュボード - 要件定義書

## 1. 概要

社内ネットワーク上にある3〜5台のUbuntu/Debianサーバーの利用状況をリアルタイムに可視化するダッシュボードを構築する。「誰が、どのサーバーを、どのくらい使っているか」を一目で把握できるようにすることが目的。

---

## 2. 機能要件

| # | 機能 | 詳細 |
|---|------|------|
| F1 | サーバー管理 | 設定ファイル（YAML）にサーバー名・IP・SSHユーザーを登録。監視サーバー自身も `host: localhost` で登録し、全サーバー同一ロジック（SSH）でデータ収集する |
| F2 | プロセス/リソース使用状況 | ユーザーごとのCPU%・MEM%合計をグラフ表示 + CPU/MEM上位5件の重いプロセスをリスト表示 |
| F3 | ディスク使用状況 | サーバー全体のファイルシステム使用量 + ユーザーごとのホームディレクトリ使用量 |
| F4 | tmuxセッション可視化 | ユーザーごとのセッション数・ウィンドウ数のサマリ表示 |
| F5 | GPU使用状況 | GPU毎の使用率、メモリ使用量、温度を表示 + どのユーザーがGPUを占有しているか |
| F6 | CPU/メモリ概況 | サーバー全体のロードアベレージ、メモリ使用量、スワップ使用量 |
| F7 | リアルタイム更新 | バックエンド30秒間隔でデータ収集、フロントエンド10秒間隔でポーリング |

---

## 3. 非機能要件

- **履歴データ不要**: 現在のスナップショットのみ表示（DB不要、インメモリ保持）
- **デプロイ先**: 社内ネットワーク内のサーバー
- **対象OS**: 全サーバーがUbuntu/Debian系

---

## 4. SSH認証方針

- **SSH鍵認証**で接続（パスワード認証は使用しない）
- 監視専用ユーザー（例: `monitor`）を各対象サーバーに作成し、最小権限のみ付与
- `authorized_keys` でIP制限を追加
- 鍵の管理・権限設定の詳細はデプロイ手順として別途記載

---

## 5. 対象外

- ディレクトリルールによる案件特定
- 履歴データの蓄積・トレンド表示

---

## 6. アーキテクチャ

```
                        ┌──────────────────┐
                   SSH  │  対象サーバー 1   │
              ┌───────> └──────────────────┘
              │    SSH  ┌──────────────────┐
              ├───────> │  対象サーバー 2   │
              │         └──────────────────┘
              │    SSH  ┌──────────────────┐
              ├───────> │  対象サーバー 3   │
              │         └──────────────────┘
┌─────────────┴─────────────┐
│  監視サーバー              │
│                           │
│  ┌───────────────┐        │
│  │ FastAPI        │        │
│  │  (port 8000)   │        │
│  └───────┬───────┘        │
│          │ serves          │
│  ┌───────▼───────┐        │
│  │ React (静的)   │        │
│  └───────────────┘        │
│                           │
│  [インメモリストア]        │
│  [config.yaml: サーバー一覧]│
└───────────────────────────┘
```

### データフロー

1. `config.yaml` からサーバー一覧（名前・IP・SSHユーザー）を読み込み
2. バックグラウンドタスク（30秒周期）が各サーバーに `asyncssh` で非同期SSH接続（並行実行）
3. 1セッションで全収集コマンドを一括実行しパース
4. 結果をインメモリのdictに格納
5. フロントエンドが `/api/status` を10秒間隔でポーリングして表示更新

---

## 7. データ収集方法

各サーバーへの1回のSSHセッションで以下のコマンドをセクション区切りで一括実行:

| データ | コマンド | 補足 |
|--------|---------|------|
| プロセス一覧 | `ps aux --no-headers` | ユーザー別にCPU%・MEM%を集計 + 上位5件の重いプロセスを抽出 |
| ファイルシステム使用量 | `df -h --output=source,fstype,size,used,avail,pcent,target` | パーティション別 |
| ユーザー別ディスク | `timeout 10 du -sh /home/*` | ホームディレクトリサイズ（タイムアウト付き） |
| tmuxセッション | `/tmp/tmux-*/` ソケット探索 → `tmux -S <socket> list-sessions` | ユーザーごとのセッション数・ウィンドウ数をサマリ取得 |
| GPU使用状況 | `nvidia-smi --query-gpu=index,name,utilization.gpu,utilization.memory,memory.used,memory.total,temperature.gpu --format=csv,noheader` | GPU毎のステータス |
| GPUプロセス | `nvidia-smi --query-compute-apps=pid,used_memory,gpu_name --format=csv,noheader` + `ps -p <pid> -o user=` | PIDからユーザーを紐付け |
| CPU/メモリ概況 | `free -h` + `nproc` + `uptime` | ロードアベレージ、メモリ/スワップ使用量、CPU数 |

## 8. 技術スタック

### バックエンド (Python 3.14 / uv)

| ライブラリ | 用途 |
|-----------|------|
| FastAPI | APIサーバー + 静的ファイル配信 |
| asyncssh | 非同期SSH接続（FastAPIと相性良好） |
| Pydantic v2 | データモデル・バリデーション |
| pydantic-settings | 環境変数・設定管理 |
| uvicorn | ASGIサーバー |

### フロントエンド

| ライブラリ | 用途 |
|-----------|------|
| React 19.2 + TypeScript 5.9 | UI構築 |
| React Router 7.9 | ルーティング |
| Vite 6.3 | ビルドツール |
| Tailwind CSS 4.1 | スタイリング |
| TanStack Query | データフェッチ・自動ポーリング |

### インフラ

- **DB不要** - インメモリでスナップショット保持
- **デプロイ** - 社内ネットワーク内のUbuntuサーバー
- **サーバー管理** - `config.yaml` に手動登録（IPアドレス・ホスト名・SSHユーザー）

---

## 9. 考慮事項・リスク

| リスク | 対策 |
|--------|------|
| tmuxソケットの権限問題 | SSH接続ユーザーにsudo権限付与、または `/tmp/tmux-*/` ソケットをfindで探索 |
| `du` が大容量ホームディレクトリで遅延 | `timeout 10` で制限 |
| SSH接続失敗 | 接続タイムアウト5秒、エラーをUI表示 |
| データが古い場合の表示 | 2分以上更新なしのデータはUIで警告表示 |
| nvidia-smi未インストールのサーバー | コマンドエラーをキャッチし、GPU情報なしとして表示（GPUなしサーバーでもエラーにならない） |
